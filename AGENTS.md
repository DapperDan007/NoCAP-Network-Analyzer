# NoCAP Network Analyzer workspace

This is a self-hosted Docker application. The web interface is named PCAP Lens.

## GitHub synchronization

The user wants completed Codex changes in this workspace synchronized to `https://github.com/DapperDan007/NoCAP-Network-Analyzer.git`.

- After completing requested source changes, run the checks appropriate to the change, inspect the diff, commit the relevant changes, and push the current work branch to `origin` by default. This workflow is authorized unless the user asks for local-only work or says to defer syncing. Native tool approvals still apply.
- Preserve remote history and other contributors' work. Fetch before pushing; reconcile remote changes without force-pushing. If branch protection requires a pull request, use a `codex/` branch and report its link instead of bypassing protection.
- Stage only task-related files. Do not commit unrelated user changes, captures (`.pcap`, `.pcapng`, `.cap`, compressed captures), analysis reports, downloaded threat indicators, Docker volume contents, `.env` files, tokens, credentials, or private keys. `data/` is private runtime state.
- Keep `.env.example` free of real secrets. Synthetic packet fixtures should be generated by `scripts/make-fixture.mjs`, not committed as binary captures.
- Git synchronization is performed at task completion; do not install background watchers, hooks, recurring automations, or automatic push services unless requested.

## Verification

- No npm packages are needed. `node --test test/map.test.mjs test/analyzer.test.mjs` checks pure application logic.
- Full verification uses `docker build --target test -t pcap-lens-test .` then `docker run --rm --network none --tmpfs /tmp:rw,size=256m pcap-lens-test`. This includes real TShark parsing and HTTP integration tests.
- After UI changes, use the supported browser tools to verify the affected interactions when available.
- Production is started with `docker compose up --build -d`; preserve the `capture-data` volume during updates.
